# 문장 성분 조합 게임

수업 시간에 약 30명이 10분 안팎으로 함께 하는 자기소개용 게임입니다.
진행은 빔프로젝터에 띄운 **호스트 화면**에서 하고, 참가자는 **자기 폰**으로 문장 성분 하나만 입력해요.

- 3명이 한 조가 되어, 서로의 답을 보지 못한 채 **주어 / 부사어 / 서술어** 같은 성분을 한 칸씩 써요.
- 조원들이 쓴 칸을 이어 붙이면 한 문장이 완성돼요. 엉뚱하게 이어진 문장을 보면서 함께 웃어요.
- AI(Gemini)가 모든 조의 문장을 한 번에 읽고 **적격성**(문법·성분 역할)과 **문맥**(상황과 이어지는가)으로 점수를 매겨요.
- 5라운드가 하나의 이야기로 이어지고, 마지막에 처음 장면(냉장고 문)으로 돌아와요.

> 코딩을 몰라도 따라 할 수 있게 썼어요. 처음부터 끝까지 한 번 따라 하는 데 30분쯤 걸려요.

## 1. 먼저 구경하기: 로컬 테스트 모드

Firebase도 AI 키도 없이, **노트북 한 대의 브라우저 탭 여러 개**로 게임 전체를 돌려볼 수 있어요. 리허설용이에요.

1. 이 저장소의 파일을 내려받아 폴더째 둡니다. (GitHub에서 초록색 **Code** 버튼 → **Download ZIP** → 압축 풀기)
   이미 배포했다면 배포한 사이트 주소로 열어도 똑같아요.
2. `index.html`을 더블클릭해서 **Chrome**이나 **Edge**로 엽니다.
3. **⚙ 설정** → **1. 연결 방식**에서 **로컬 테스트 모드**를 고르고 **저장**.
4. **새 게임 만들기**를 누르면 QR코드가 나와요.
5. 위쪽 막대의 **＋참가자 탭**을 누르면 참가자 화면이 새 탭으로 열려요. 이름을 넣고 입장해 보세요.
   탭을 여러 개 열면 사람도 여러 명이 돼요.
6. 사람이 모자라면 **👥 참가자·봇** → **+10** 처럼 가짜 참가자(봇)를 넣어요. 봇은 1~12초 안에 미리 정해 둔 낱말을 내요.
7. **조 편성하기 ▶** → **1라운드 시작 ▶** … 순서대로 눌러 보세요.
   AI 키가 없으면 **✍️ 직접 채점**으로 점수를 넣으면 돼요.

> 로컬 테스트 모드는 같은 브라우저의 탭끼리만 연결돼요. 다른 폰은 들어올 수 없어요.
> 실제 수업에서는 아래 2~5단계를 마친 뒤 **Firebase** 모드로 진행해요.

## 2. Firebase 데이터베이스 만들기

참가자 폰과 호스트 화면을 실시간으로 이어 주는 무료 데이터베이스예요. (Google 계정 필요, 카드 등록 필요 없음)

### 2-1. 프로젝트 만들기

1. <https://console.firebase.google.com> 에 Google 계정으로 들어갑니다.
2. **프로젝트 만들기**(또는 **Firebase 프로젝트 시작하기**)를 누릅니다.
3. 프로젝트 이름을 적어요. 예: `sentence-game`
4. 약관에 동의하고 계속. **Google 애널리틱스**나 **Gemini in Firebase**를 켤지 물으면 **꺼도 돼요**.
5. **프로젝트 만들기**를 누르고 1분쯤 기다리면 끝.

### 2-2. Realtime Database 만들기

1. 왼쪽 메뉴에서 **빌드(Build)** → **Realtime Database**를 누릅니다.
   (메뉴가 안 보이면 **모든 제품** 또는 검색창에서 `Realtime Database`를 찾아요. **Firestore**가 아니라 **Realtime Database**예요!)
2. **데이터베이스 만들기**를 누릅니다.
3. **위치**: **싱가포르 (asia-southeast1)** 를 고르세요. 한국에서 가장 가까워서 빨라요.
4. **보안 규칙**: **잠금 모드로 시작**을 고르고 **사용 설정**.

### 2-3. 보안 규칙 붙여넣기

1. Realtime Database 화면 위쪽의 **규칙** 탭을 누릅니다.
2. 편집창의 내용을 **모두 지우고**, 이 저장소의 [`database.rules.json`](database.rules.json) 파일 내용을 **통째로 복사해서 붙여넣어요**.
3. **게시**를 누릅니다.

이 규칙이 하는 일:

- 방 코드(영어 대문자 4자리)를 아는 사람만 그 방을 읽고 쓸 수 있어요. 방 목록을 훑어보는 건 막혀요.
- 이름은 20자, 답은 60자를 넘을 수 없어요.
- **입력 시간이 끝난 뒤에 들어온 답은 서버가 거절**해요.

> Firebase가 "보안 규칙이 공개되어 있다"는 경고 메일을 보낼 수 있어요.
> 로그인 없이 QR로 들어오는 게임이라 어쩔 수 없는 부분이에요. 그래서 **수업이 끝나면 기록을 지우는 것**을 권해요(게임 마지막 화면의 **🗑 기록 지우고 끝내기**).

### 2-4. 데이터베이스 주소 복사하기

**데이터** 탭 위쪽에 이런 주소가 보여요. 주소 옆 🔗 아이콘을 누르면 복사돼요.

```
https://sentence-game-default-rtdb.asia-southeast1.firebasedatabase.app
```

이 주소를 메모장에 붙여 두세요. **5단계**에서 호스트 설정에 넣어요.

> **무료(Spark) 요금제로 충분해요.** 동시 접속 100명, 저장 1GB, 월 다운로드 10GB까지 무료예요. 30명이 10분 하는 데 몇 MB 정도밖에 안 써요.

## 3. Gemini API 키 받기

AI 채점에 쓰는 키예요. 없어도 게임은 되고, 그때는 점수를 직접 입력해요.

1. <https://aistudio.google.com> 에 Google 계정으로 들어갑니다.
2. **Get API key**(API 키 가져오기)를 누릅니다.
3. **API 키 만들기(Create API key)** → 프로젝트를 고르라고 하면 아무거나(새로 만들거나, 2단계의 Firebase 프로젝트) 골라요.
4. `AIza…`로 시작하는 키가 나오면 **복사**해서 메모장에 붙여 둡니다.

알아 둘 점:

- **무료 등급**은 분당·하루 요청 수 한도가 있어요. 이 게임은 라운드마다 **한 번**만 부르니(한 판에 5번) 충분해요.
- 무료 등급에서는 보낸 내용이 Google 서비스 개선에 쓰일 수 있어요. 이 게임은 **참가자 이름은 보내지 않고**, 상황 문장과 조 번호, 각 칸의 낱말만 보내요.
- 키는 **호스트 노트북의 브라우저(localStorage)에만** 저장돼요. 코드·데이터베이스·QR 링크 어디에도 들어가지 않고, AI 호출도 호스트 화면에서만 해요.
- (선택, 더 안전하게) Google Cloud 콘솔의 **API 및 서비스 → 사용자 인증 정보**에서 이 키를 고른 뒤, **애플리케이션 제한사항 → 웹사이트**에 내 사이트 주소(예: `https://tiifosia.github.io/*`)만 허용해 두면 키가 새어도 다른 곳에서 못 써요. 이렇게 하면 로컬 파일로 연 화면에서는 AI 채점이 안 되니 참고하세요.

## 4. 사이트 배포하기

파일만 올리면 되는 정적 사이트라 서버가 필요 없어요.

### 방법 A. GitHub Pages (권장)

이 저장소(`tiifosia/game2`)에서 바로 켤 수 있어요.

1. GitHub에서 저장소 페이지를 엽니다.
2. 위쪽 **Settings** → 왼쪽 **Pages**.
3. **Build and deployment**의 **Source**: **Deploy from a branch**.
4. **Branch**: 사이트 파일이 있는 브랜치를 고르고(예: `main`, 또는 지금 작업한 `claude/practical-hamilton-xlwzwo`), 폴더는 **/ (root)** → **Save**.
5. 1~3분 뒤 같은 화면 위쪽에 주소가 나와요.

```
https://tiifosia.github.io/game2/
```

- 이 주소가 **호스트 화면**이에요. 참가자는 이 주소가 아니라 게임을 시작하면 나오는 **QR코드**로 들어와요.
- 저장소가 **Private**이고 무료 계정이면 Pages를 켤 수 없어요. 저장소를 **Public**으로 바꾸거나(코드 안에 비밀 정보는 없어요) 방법 B를 쓰세요.
- 파일을 고쳐서 올리면 몇 분 뒤 사이트에도 반영돼요. 바로 안 바뀌면 브라우저에서 **Ctrl+Shift+R**(맥은 **Cmd+Shift+R**).

### 방법 B. Netlify Drop

1. <https://app.netlify.com/drop> 에 들어가요.
2. 사이트 폴더(`index.html`이 들어 있는 폴더)를 화면에 **끌어다 놓아요**.
3. 잠시 뒤 `https://무언가.netlify.app` 주소가 나와요.

> 로그인하지 않고 올린 사이트는 잠깐 뒤 사라질 수 있어요. 무료 계정으로 로그인해서 올리면 계속 남아요.

## 5. 호스트 설정 입력하기

**수업에 쓸 노트북**에서 한 번만 하면 돼요. (설정은 그 노트북 브라우저에 저장돼요. 다른 노트북이나 다른 브라우저를 쓰면 다시 넣어야 해요.)

1. 배포한 사이트 주소를 Chrome/Edge로 엽니다.
2. **⚙ 설정**을 누릅니다.
3. **1. 연결 방식** → **Firebase** 선택 → 2-4단계에서 복사한 주소를 붙여넣고 **연결 테스트**.
   `✅ 연결 성공! 읽기·쓰기 모두 돼요.`가 나오면 성공.
4. **2. AI 채점** → 3단계의 키를 붙여넣고 **모델 목록 불러오기**.
   맨 위 모델(추천, 보통 `flash` 계열)을 그대로 두고 **AI 연결 확인** → `✅ AI 응답: …`이 나오면 성공.
   - 모델 이름은 자주 바뀌어요. 목록은 키로 그때그때 불러오니, 수업 전날 한 번 더 불러오면 가장 최신 모델을 쓸 수 있어요.
   - **AI에게 덧붙일 말**에 "신조어도 너그럽게 봐 줘"처럼 채점 분위기를 적을 수 있어요(선택).
5. **3. 게임 규칙**: 제한시간(기본 60초), 적격성 만점(기본 5점), 문맥 만점(기본 5점).
6. **4. 라운드**: 상황 문장과 문장 구조(성분 2~4개)를 고치거나, 라운드를 더하고 뺄 수 있어요. **기본 라운드로 되돌리기**도 있어요.
7. **저장**. 처음 화면에 ✅ 표시가 세 개 보이면 준비 끝이에요.

### 기본 라운드

| 라운드 | 상황 | 조건 |
|---|---|---|
| 1 | 어느 평범한 월요일 아침, 냉장고 문을 열었더니… | 주어 + 부사어 + 서술어 |
| 2 | 이 소식은 순식간에 퍼져 대통령의 귀에까지 들어갔다. 대통령은… | 목적어 + 부사어 + 서술어 |
| 3 | 그날 밤, 하늘에서 거대한 그림자가 천천히 내려왔다. 그림자 속에서… | 관형어 + 주어 + 서술어 |
| 4 | 모두가 숨을 죽인 순간, 누군가 외쳤다. "잠깐! 사실은…" | 주어 + 보어 + 서술어 |
| 5 | 그리고 다음 날 아침, 냉장고 문을 다시 열었더니… | 주어 + 목적어 + 서술어 |

## 6. 게임 진행 방법

| 순서 | 호스트 화면 (빔프로젝터) | 참가자 폰 |
|---|---|---|
| 입장 | **새 게임 만들기** → 큰 QR코드와 입장한 사람 이름이 떠요 | QR을 찍고 이름 입력 → **입장하기** |
| 조 편성 | **조 편성하기 ▶** → 3명씩 무작위로 조가 나와요. 마음에 안 들면 **🔀 다시 섞기** | "N조"와 조원 이름 |
| 라운드 | **1라운드 시작 ▶** → 상황, 문장 구조, 남은 시간, 조별 제출 현황(●) | 내가 맡은 성분 입력칸 + 한 줄 힌트 → **제출하기** → "앞 화면을 봐 주세요" |
| 마감 | 시간이 끝나거나 **전원이 제출하면 자동 마감**. **⏱ +15초**, **지금 마감**도 있어요 | 마감 1초 전, 써 놓고 안 낸 글은 자동 제출 |
| 공개 | 조별 문장이 차례로 나타나요. 칸마다 쓴 사람 이름, 안 쓴 칸은 **(빈칸)** | 앞 화면 보기 |
| AI 채점 | **🤖 AI 채점** → 조별 적격성·문맥 점수와 한 줄 이유. 표에서 **직접 고친 뒤** **점수 확정 ✓** | 앞 화면 보기 |
| 결과 | 조별 점수와 이유 → **누적 순위 보기 ▶** | 이번 라운드 점수, 현재 순위 |
| 다음 | **2라운드 시작 ▶** … 5라운드까지 | 맡는 성분이 라운드마다 바뀌어요 |
| 끝 | **최종 결과 보기 🏆** → 🏆 최종 순위 / 📖 조별 이야기 / 📋 전체 문장 | 우리 조 최종 순위 |

### 알아 두면 좋은 기능

- **발표용 리모컨**: `→`, `Space`, `PageDown`을 누르면 화면의 주황색 진행 버튼이 눌려요. (점수 확정은 실수 방지를 위해 직접 눌러야 해요)
- **위쪽 작은 막대**
  - **QR**: 늦게 온 사람을 위해 QR코드를 다시 띄워요. **🔗 링크 복사**로 단톡방에 링크를 보낼 수도 있어요.
  - **👥 참가자·봇**: 봇 추가, 나간 사람 내보내기(✕).
  - **🔊**: 마감 3초 전 삐 소리 켜기/끄기. **⛶**: 전체 화면.
  - **새 게임**: 지금 게임을 닫고 처음 화면으로.
- **AI가 실패해도 괜찮아요**: 한도 초과·인터넷 문제로 실패하면 이유가 나오고, 표에 점수를 직접 넣으면 돼요. **🤖 AI 다시 채점**도 할 수 있어요.

### 세부 규칙

- **조 나누기**: 3명 조가 기본. 인원이 3으로 안 나누어떨어지면 2명 조를 만들어요(4명 조는 없어요). 예: 31명 → 3명 조 9개 + 2명 조 2개.
- **2명 조**: 한 사람이 성분 2개를 맡고, 라운드마다 번갈아 맡아요.
- **맡는 성분**: 라운드마다 한 칸씩 돌아가며 바뀌어요.
- **늦게 온 사람**: 조 편성 뒤에 들어오면 **2명 조**에 먼저 들어가고, 2명 조가 없으면 새 조를 만들어요(그다음 늦게 온 사람은 그 조부터 채워요). 라운드 중간에 들어오면 그 라운드는 쉬고 **다음 라운드부터** 참여해요.
- **새로고침해도 그대로**: 폰을 새로고침해도 이름과 조가 그대로예요. 탭을 닫았다가 QR로 다시 들어오면 **‘이름’으로 계속하기** 버튼이 나와요. 호스트 화면을 새로고침해도 게임이 그대로 이어져요.
- **빈칸**: 시간 안에 안 쓴 칸은 (빈칸)으로 공개되고, AI도 빈칸을 감점해요.
- **점수**: 라운드마다 적격성 0~5점 + 문맥 0~5점 = 최대 10점(설정에서 바꿀 수 있어요). AI는 모든 조를 서로 비교해서 점수가 고르게 갈리도록 매겨요. 누적 점수가 가장 높은 조가 우승(동점이면 공동 우승).
- **이름 중복**: 같은 방에 같은 이름은 못 써요. 성이나 별명을 붙이게 안내해요.

### 시간 계산

라운드 한 번 ≈ 입력 60초 + 공개 30초 + 채점·결과 40초 + 순위 20초 ≈ 2분 30초 → 5라운드 ≈ **12분**.
10분에 맞추고 싶으면 제한시간을 **45초**로 줄이세요.

## 8. 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| 연결 테스트에서 "권한이 없어요" | 2-3단계 보안 규칙을 붙여넣고 **게시**를 눌렀는지 확인 |
| 연결 테스트에서 "10초 안에 응답이 없어요" | 주소를 **데이터 탭에서 그대로** 복사했는지 확인(`firebasedatabase.app` 또는 `firebaseio.com`으로 끝나요). Firestore 주소가 아닌지 확인 |
| 폰에서 "방을 찾을 수 없어요" | 호스트가 **새 게임**을 다시 만들었거나 기록을 지운 경우예요. 화면의 **새 QR**을 다시 찍어요 |
| 폰에서 "연결이 끊겼어요" | 와이파이 ↔ LTE를 바꿔 보세요. 다시 연결되면 저절로 이어져요 |
| 위쪽에 "연결 끊김" (호스트) | 노트북 인터넷 확인. 다시 연결되면 저절로 이어지고, 그사이 누른 버튼도 반영돼요 |
| "다른 창에서 진행 중이에요" | 호스트 화면을 두 개 열었을 때 나와요. 실제로 쓸 창에서 **이 창에서 진행하기** |
| AI: "API 키가 올바르지 않아요" | 키를 다시 복사해서 넣기(앞뒤 공백 주의) |
| AI: "무료 사용량 한도에 걸렸어요" | 1분 뒤 **AI 다시 채점**, 또는 설정에서 다른 모델(예: `flash-lite`) 고르기, 또는 직접 채점 |
| AI: "이 모델을 찾을 수 없어요" | 모델이 없어졌어요. 설정에서 **모델 목록 불러오기** 후 다시 고르기 |
| 고친 파일이 사이트에 반영이 안 돼요 | GitHub Pages는 1~3분 걸려요. 그 뒤 **Ctrl+Shift+R**로 새로고침 |
| 로컬 테스트에서 참가자 탭이 호스트와 안 이어져요 | 호스트와 참가자 탭을 **같은 브라우저**에서 열어야 해요. 시크릿 창이나 다른 브라우저(Chrome ↔ Edge)끼리는 안 이어져요. 호스트의 **＋참가자 탭** 버튼으로 여는 게 가장 확실해요 |

## 9. 파일 구성과 동작 원리

```
index.html             호스트(빔프로젝터) 화면
play.html              참가자(폰) 화면 — QR코드가 이 주소를 가리켜요
css/style.css          디자인
js/common.js           공통 규칙: 문장 성분 힌트, 기본 라운드, 조 편성, 성분 돌아가기, 점수 계산, 봇 낱말
js/store.js            실시간 저장소: 로컬 테스트(localStorage) / Firebase Realtime Database
js/ai.js               Gemini 호출: 모델 목록, 채점 요청과 응답 정리
js/host.js             호스트 진행 전부: 화면, 타이머, 자동 마감, 늦은 입장, 봇, 채점, 설정
js/play.js             참가자 화면: 입장, 내 조, 성분 입력, 제출
lib/                   함께 넣어 둔 라이브러리(Firebase SDK, QR코드 생성기) — lib/LICENSES.md
database.rules.json    Firebase 보안 규칙(2-3단계에서 붙여넣기)
```

- **QR 링크**에는 `play.html?room=방코드&db=데이터베이스주소`만 들어가요. API 키는 들어가지 않아요.
- **호스트만** 게임 상태(단계, 조, 담당 성분, 점수)를 쓰고, 참가자는 **자기 이름과 자기 답만** 써요.
- 데이터베이스 안의 모양:

```
rooms/방코드/
  meta       만든 시각, 진행 중인 호스트 창, 게임 설정(라운드·제한시간·만점)
  state      지금 단계(lobby·teams·input·reveal·scoring·scored·ranking·final), 라운드, 마감 시각
  players    참가자 이름 (봇은 bot: true)
  teams      조 번호와 조원
  roundInfo  라운드를 시작할 때 고정한 상황 문장과 문장 구조
  roles      라운드별 칸 담당
  answers    라운드별 조별 칸별 답
  draft      AI 채점 결과(확정 전)
  scores     확정된 점수와 한 줄 이유
```
